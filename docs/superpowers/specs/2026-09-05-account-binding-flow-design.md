# 账号绑定流程修复设计

## 1. 目标

修复账号管理中的扫码绑定、重新登录和账号列表刷新流程。首版完整支持抖音真实身份绑定，同时修复小红书、视频号、抖音和快手共用的 SSE 认证与会话管理问题。

验收结果：已授权桌面端能够建立扫码连接；扫码成功后保存真实抖音身份与有效 Cookie；重复扫码同一抖音账号不会产生重复记录；重新登录不会误绑其他账号；普通账号列表查询不再触发全量 Cookie 检测或修改账号状态。

## 2. 范围

### 2.1 本次包含

- 修复 `GET /login` 的 SSE token 校验。
- 使用独立登录会话标识管理并发扫码任务。
- 抖音扫码后获取真实的平台账号 ID 和昵称。
- 为本地账号补充平台身份字段、时间字段及唯一约束。
- 支持同一抖音账号幂等绑定和安全重新登录。
- 原子化保存 Cookie 与账号记录，并清理失败或被替换的 Cookie 文件。
- 将账号列表查询与 Cookie 有效性检测解耦。
- 补充聚焦的后端与前端回归测试。

### 2.2 本次不包含

- 小红书、视频号和快手的真实平台身份解析与去重。
- 云端对标账号同步、iOS 口播同步或云端用户表改造。
- 修改发布、数据采集或平台上传协议。
- 自动迁移或合并现有的重复账号记录。

## 3. 总体架构

账号绑定分为四个明确阶段：

1. 前端创建带随机 `loginSessionId` 的 SSE 连接。
2. 后端验证桌面授权 token，创建仅属于该连接的状态队列并启动平台登录任务。
3. 平台登录模块完成扫码、Cookie 校验和真实身份解析。
4. 账号服务在事务中执行幂等绑定，提交成功后再向 SSE 发送成功事件。

路由层只负责参数、认证和 SSE 响应；登录编排放在 `backend_app/modules/accounts/login_service.py`；账号查询和写入放在 `backend_app/modules/accounts/repository.py`；平台浏览器操作保留在 `myUtils/login.py`，但返回结构化登录结果，不直接写数据库。

## 4. SSE 认证与登录会话

### 4.1 token 规则

普通 API 继续只接受 `Authorization: Bearer <token>`。由于原生 `EventSource` 无法设置自定义请求头，只有 `GET /login` 可以从 `token` 查询参数读取 token。

查询参数 token 必须经过与请求头 token 相同的序列化器、最大有效期和 `license:` 身份校验。缺失、签名错误、过期或不属于许可证身份时返回 HTTP 401，且不得启动浏览器线程。

token 出现在 URL 中存在日志泄露风险，因此后端日志不得打印完整查询字符串，前端不得把 URL 或 token 写入控制台。该兼容方式仅限本地回环服务；不得扩展到其他接口。

### 4.2 登录会话

前端为每次添加或重新登录生成随机 `loginSessionId`，后端使用该值作为会话键。账号名称不能再作为队列键。

同一会话标识重复使用时返回 HTTP 409。SSE 正常结束、客户端断开、超时或任务异常时都必须清理队列和注册表。单个桌面运行时允许多个不同会话并行，但同一已有账号只允许一个重新登录任务。

SSE 事件改为结构化 JSON：

- `qr_ready`：包含二维码数据。
- `binding`：扫码完成，正在验证身份。
- `success`：包含绑定后的账号摘要。
- `error`：包含稳定错误码和面向用户的信息。
- `timeout`：登录会话超时。

为了兼容当前页面，本次前后端同时升级，不继续保留以字符串 `200`、`500` 表示结果的旧协议。

## 5. 数据结构与迁移

在现有 `user_info` 表增加：

| 字段 | 类型 | 规则 |
|---|---|---|
| `platform_user_id` | `TEXT NULL` | 平台稳定用户 ID；旧数据及暂不支持身份解析的平台允许为空 |
| `display_name` | `TEXT NULL` | 平台返回的真实昵称 |
| `remark_name` | `TEXT NULL` | 用户自定义备注；原 `userName` 数据迁入此字段 |
| `last_validated_at` | `DATETIME NULL` | 最近一次明确验证成功时间 |
| `last_error_code` | `TEXT NULL` | 最近一次检测失败的稳定错误码 |
| `created_at` | `DATETIME` | 默认当前时间 |
| `updated_at` | `DATETIME` | 默认当前时间，写入时显式更新 |

建立部分唯一索引，约束非空平台身份：

```sql
CREATE UNIQUE INDEX IF NOT EXISTS uk_user_info_platform_identity
ON user_info(type, platform_user_id)
WHERE platform_user_id IS NOT NULL;
```

保留 `userName` 作为兼容字段，响应阶段优先显示 `remark_name`，其次 `display_name`，最后 `userName`。本次迁移只补字段和索引，不猜测旧数据的平台身份，也不自动删除重复记录。

## 6. 抖音绑定规则

### 6.1 新增账号

抖音登录模块保存临时 storage state，使用该临时状态调用现有 Cookie 检查，并从已登录创作者页面或可靠账号接口获取 `platform_user_id` 和真实昵称。

验证和身份解析都成功后，账号服务按 `(type=3, platform_user_id)` 查询：

- 不存在：创建账号记录。
- 已存在：更新该记录的 Cookie、真实昵称和有效状态，返回“已有账号已更新”，不插入重复行。

用户输入的账号名称仅作为 `remark_name`，不作为平台身份或唯一键。

### 6.2 重新登录

重新登录必须携带现有 `userInfoId`。服务先确认记录存在且平台类型为抖音，再完成扫码和真实身份解析。

- 新身份与原 `platform_user_id` 相同：允许替换 Cookie。
- 原记录没有 `platform_user_id`：允许首次补全，但如果该身份已属于另一记录，则返回冲突，不自动合并。
- 新身份与原身份不同：拒绝更新，返回 `ACCOUNT_IDENTITY_MISMATCH`，保留原账号和原 Cookie。

## 7. Cookie 文件事务边界

新 Cookie 先写入 `cookiesFile/.pending/<loginSessionId>.json`。平台验证失败、身份解析失败、数据库冲突或任务取消时删除临时文件。

成功流程：

1. 验证临时 Cookie。
2. 解析真实平台身份。
3. 开启数据库事务并执行新增或更新。
4. 将临时文件原子移动为随机正式文件名。
5. 更新数据库 `filePath` 并提交事务。
6. 提交成功后删除被替换的旧 Cookie 文件。
7. 发送 SSE `success`。

数据库失败时回滚，并删除尚未生效的新文件。旧文件只在新记录成功提交后删除，防止重新登录失败导致账号不可用。文件路径必须解析并验证位于 `cookiesFile` 下，禁止删除目录外文件。

## 8. 账号查询和状态检测

`GET /getValidAccounts` 改为纯查询，返回命名对象而不是依赖 SQLite 列顺序的数组。响应包含账号 ID、平台、显示名称、备注、状态、最近验证时间和最近错误码。

新增单账号检测接口：

```text
POST /accounts/{account_id}/validate
```

该接口明确执行 Cookie 验证并更新状态。临时网络错误返回检测失败，但不立即把账号永久标记为失效；只有平台明确返回未登录或 Cookie 失效时才设置 `status=0`。列表页面可以手动检测单个账号，后台任务后续可复用相同服务。

## 9. 错误处理

稳定错误码至少包括：

- `AUTH_TOKEN_INVALID`
- `LOGIN_SESSION_CONFLICT`
- `LOGIN_TIMEOUT`
- `QR_CODE_UNAVAILABLE`
- `COOKIE_INVALID`
- `ACCOUNT_IDENTITY_UNAVAILABLE`
- `ACCOUNT_IDENTITY_MISMATCH`
- `ACCOUNT_ALREADY_BOUND`
- `ACCOUNT_NOT_FOUND`
- `PLATFORM_UNSUPPORTED`

平台异常不得直接把堆栈、Cookie、token、本地完整路径或平台原始敏感响应返回前端。详细上下文进入服务端日志，面向用户的消息说明是否可以重试。

## 10. 前端行为

账号表单中的“账号名称”改为“账号备注（可选）”。扫码成功后列表展示真实昵称；有备注时同时展示备注。

页面按结构化 SSE 事件更新二维码、验证中、成功、失败和超时状态。组件卸载、对话框关闭或开始新会话时关闭旧 EventSource。成功事件直接携带账号摘要，随后执行一次纯列表刷新。

重新登录页面明确展示目标账号；如果扫码身份不一致，保留对话框并提示用户使用正确账号扫码。

## 11. 测试与验证

后端测试覆盖：

- `/login` 接受有效查询 token，拒绝缺失、过期、签名错误和非许可证 token。
- 认证失败时不启动登录线程。
- 同名账号使用不同会话互不覆盖，会话在所有退出路径被清理。
- 新抖音身份创建、重复身份幂等更新、重新登录同号成功和错号拒绝。
- 临时 Cookie 在失败时删除，成功时替换，数据库失败时保留旧文件。
- 部分唯一索引允许旧记录身份为空，但拒绝重复的非空平台身份。
- 账号列表 GET 不调用 Cookie 检查且不修改数据库。
- 单账号检测区分明确失效与临时网络错误。

前端测试覆盖 URL 参数编码、结构化 SSE 事件映射、关闭连接和错号提示。验证命令以仓库现有 pytest 测试为主，并执行前端构建或项目可用的测试命令。

## 12. 发布与兼容

数据库迁移必须幂等。旧账号在迁移后仍可展示和发布；其 `platform_user_id` 为空，下一次成功重新登录时补全身份。

本次前端与后端必须作为同一版本发布，因为 SSE 消息协议会同步升级。若桌面应用存在前后端独立升级场景，则发布前增加短期协议版本参数，并在后端保留一个版本周期的旧消息兼容；当前一体化桌面包不需要该兼容层。

回滚代码时新增字段可保留，不影响旧代码读取原字段；唯一索引无需删除。任何迁移和清理操作都不得删除现有账号或 Cookie。
